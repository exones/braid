## Changes introduced

The previous planning instructions required `backlog/<ID>-<slug>.md` and never defined `<ID>`. The skill said to split work into stories, tasks, and spikes and to fill the templates. The seed note listed purpose-based letters such as `N` and `I` next to `A`–`D`. A new epic could follow every written instruction and still produce title-derived names such as `F-publish-facts.md`, `O-oidc-guard.md`, `S-install-scripts.md`, and `U-npm-account.md`.

The workflow section now says:

- Stories, tasks, and spikes share one sequence, assigned in the order of the epic table when the backlog is first recorded: `A`, `B`, `C`, `D`, through `Z`, then `AA`, `AB`, in spreadsheet-column order.
- A new ID is uppercase letters with no digits. The fourth item is `D` for any kind.
- The filename is `backlog/<ID>-<descriptive-slug>.md`. The ID is the token before the first hyphen. The epic table, dependency references, `checkpoints/<ID>.md`, and `reports/<ID>.md` use that same ID.
- Feature labels and reviews do not take a letter from this sequence. Review names stay in the existing review section.
- After the backlog is recorded, IDs, filenames, and valid links stay. Reordering does not rename files. A cancelled ID stays reserved. A later item receives the earliest sequence ID that no file in that epic's `backlog/` directory already uses.
- AGENTO-001 keeps `A`, `B`, `C`, `D`, `N`, `D1`, and `I`. `D1` stays this story's ID. A new epic starts at `A`. `backlog/R-review.md` already occupies `R`.

On this tree, `epics/agento/001-seed/backlog/` uses `A`, `B`, `C`, `D`, `D1`, `I`, `N`, and `R`. The earliest free sequence ID is `E`. That inventory is not an assignment of `E`.

README, `AGENTS.md`, `docs/decisions.md`, and `docs/agent-handoff.md` do not restate the sequence. README already links `docs/agile-workflow.md`. No product, CLI, schema, package, script, or Actions file changed. `epics/agento/002-trusted-publish/` was not inspected or edited. No agent was launched.
