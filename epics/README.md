# Epics

Each epic records what was asked, decided and delivered, so work can resume without chat history. How epics and items work is in the [workflow](../.agents/skills/braid-coordinate/references/workflow.md).

- [braid 001: seed](braid/001-seed/epic.md): first CLI, manual ledger, PowerShell verification, GitHub Actions, and packaged installation.
- [braid 002: trusted npm publishing](braid/002-trusted-publish/epic.md): GitHub Actions OIDC publish and the npm 12 install-script policy.
- [braid 003: worker skill](braid/003-worker-skill/epic.md): worker skill, assignment packets, resumable checkpoints, and worker-owned pull-request delivery.
- [braid 004: performance optimization](braid/004-performance-optimization/epic.md): shared versioned development toolchains.
- [braid 005: coordinator records](braid/005-coordinator-records/epic.md): cancelled before it started.

Epics 001–005 are closed. They used an earlier, heavier process; their records are kept as written and are not link-checked. Later epics follow the current workflow.
