A change to a running assignment is a new committed revision, communicated to the worker.

- **Task:** backlog path, purpose/outcome, scope/non-goals, acceptance criteria; research question/time or effort bound/decision for a spike; exact findings/revision for a scoped fix.
- **Implementation brief:** approved approach, relevant paths/patterns, settled decisions/rationale, constraints and remaining uncertainties. This is the worker's plan; repeat research only when evidence contradicts it or leaves a concrete decision unresolved.
- **Context:** AGENTS and mandated files; assigned epic/current checkpoint/item; dependency reports/checkpoints, exact accepted revisions, current merge evidence and explicit branch ordering; extra references to load only as needed. No parent-chat/dirty-parent/inspiration dependency.
- **Git contract:** actual bound root; expected initial full HEAD equal to the committed epic tip supplied at launch; clean or owned dirty tree and index; expected origin URL; named item branch to stay on (a generated branch only when this packet explicitly assigns that legacy route); explicit push destination; pull-request base (the epic branch) and any existing PR URL. A detached or mismatched binding stops writes.
- **Ownership/authority:** allowed files/resources and exclusions; report/checkpoint paths; coordinator-owned shared files; other active owners/WIP; authorized external actions. Provider authority remains AGENTS plus explicit user overrides, not this reusable template.
- **Proof:** relevant pinned toolchain/controller/schema and local commands. The deterministic offline pre-PR gate is `npm run verify`. Name external skill validators separately when skill content changes and those validators cannot run in CI. Frozen hosted workflow/event/job/step/upload requirements on every current head, including artifact digest and provenance when this packet declares them. Evidence/source-versus-PR-head mapping. State what cannot count green.
- **Continuation:** supported host mechanism. For a top-level T3 item thread, follow [T3 continuation](../references/t3-continuation.md#top-level-item-thread): link, watch, then the one catch-up snapshot in that section; if every declared check has already finished, verify and deliver in that turn, otherwise end the turn. One watch wake drives verification and one result to the named coordinator thread. The legacy parent relay is only for an explicitly selected delegated child. The worker retains diagnosis, repair, and current-head verification. On resume, supply the last root, branch, full HEAD, and pull request. Do not assume the watch survived an interruption, that repair was unassisted, or that delivery is exactly once. Name the exact blocker owner and action if the route is unavailable.
- **Outputs/return:** item report/checkpoint and required evidence, using [report format](../../../../epics/report-format.md); next permitted action/stop boundary. Pending/blocked returns are nonterminal ownership updates and still use that account when they are an item outcome or a user-attention blocker. Successful return requires independently verified current-head green checks, then coordinator acceptance/review and human merge remain separate.

For resume, add the checkpoint path and last known root/branch/full HEAD/PR/check state; interrupted action, task/process/log handles and unresolved blocker. Worker reconciles actual effects before repeating a mutation. Do not copy live status into reusable skill files.
