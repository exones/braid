- **Task:** backlog path, purpose/outcome, scope/non-goals, acceptance criteria; research question/time or effort bound/decision for a spike; exact findings/revision for a scoped fix.
- **Entry:** initial execution or resume; exact filled-packet path and concrete first useful action (named edit/test/probe). For resume, name the worker checkpoint to open first and its recorded next action.
- **Implementation brief:** approved approach, relevant paths/patterns, settled decisions/rationale, constraints and genuinely open questions. This is the worker's plan; repeat research only when evidence contradicts it or leaves a concrete decision unresolved.
- **Read now:** applicable target AGENTS obligations, assigned item and necessary current epic/checkpoint/policy sections, using exact paths/anchors. Distinguish target-project instructions from installed workflow references; reconcile mandatory project reading before dispatch rather than waiving it. No parent-chat/dirty-parent/inspiration dependency.
- **Verified dependency facts:** exact accepted revisions, actual merge evidence/references, relevant decisions and explicit branch ordering. Worker may rely on these unless inputs change or evidence conflicts; checkout and own acceptance proof remain independent.
- **Consult when needed:** historical dependency reports/checkpoints and other evidence, with exact references and the question that requires reopening them. Do not put routine history in read-now context. Reviewer evidence requirements remain separate.
- **Git contract:** actual bound root; expected initial full HEAD, clean/owned dirty tree and index; expected origin URL; generated owned branch to retain (or explicitly assigned no-track descriptive branch/full start SHA); expected upstream state (explicitly say when no upstream on a new branch is normal); first push destination; PR base and any existing PR URL. Matching facts require one verification batch, not routine fetch/history/upstream repair.
- **Ownership/authority:** allowed files/resources and exclusions; report/checkpoint paths; coordinator-owned shared files; other active owners/WIP; authorized external actions. Provider authority remains AGENTS plus explicit user overrides, not this reusable template.
- **Proof:** relevant pinned toolchain/controller/schema and local commands; frozen hosted workflow/event/job/step/upload/artifact requirements on every current head, even if branch protection is empty; evidence/source-versus-PR-head mapping. State what cannot count green.
- **Continuation:** supported host mechanism/reference and parent transport owner if applicable; worker retains diagnosis/repair/current-head verification. Supply thread/item/worktree and actual task/run lineage when available; registration generation/readiness and last consumed event/snapshot on resume. No assumed subscription durability or child polling/watch. Name exact blocker owner/action if unavailable.
- **Outputs/return:** exact owned report/checkpoint/evidence paths and an outline/example where structure is settled, using [report format](../../../../epics/report-format.md); return channel, next permitted action/stop boundary. For bounded spikes start small: question, procedure, observation table, result/limits; record observations during the trial and conclusions afterward. Pending/blocked returns are nonterminal ownership updates and still use that account when they are an item outcome or a user-attention blocker. Successful return requires independently verified current-head green checks, then coordinator acceptance/review and human merge remain separate.
