# Worker assignment: <epic>/<item>

Coordinator authoring aid: fill this one maintained template before dispatch. Workers use [braid-worker](../SKILL.md) and the exact filled packet, not this blank template. Target-project paths resolve from the assigned checkout unless absolute; installed workflow references resolve from the skill installation. Required context must exist in the assigned revision or be explicitly supplied.

Commit the filled packet at `epics/<project>/<NNN>-<slug>/assignments/<ID>.md` before creating the item checkout. A review packet, when written, uses `assignments/reviews/<parent>/<review-name>.md`. This blank asset stays here. Historical `reports/<ID>-assignment.md` files remain evidence; do not copy a live packet into both places. Supply the resulting full context SHA at launch. Do not embed this file's own commit SHA or an unknown thread or root. Record returned binding identities separately. A change to a running assignment is a new committed revision, communicated to the worker.

- **Task:** backlog path, purpose/outcome, scope/non-goals, acceptance criteria; research question/time or effort bound/decision for a spike; exact findings/revision for a scoped fix.
- **Execution skill:** full Git revision and source path of the worker skill this run uses. See [Epic branch sync and skill pinning](../../braid-coordinate/references/delivery.md#epic-branch-sync-and-skill-pinning).
- **Entry:** initial execution or resume; exact filled-packet path and concrete first useful action (named edit/test/probe). For resume, name the worker checkpoint to open first and its recorded next action.
- **Implementation brief:** approved approach, relevant paths/patterns, settled decisions/rationale, constraints and genuinely open questions. This is the worker's plan; repeat research only when evidence contradicts it or leaves a concrete decision unresolved.
- **Read now:** applicable target AGENTS obligations, the assigned item, and the epic, checkpoint, and policy sections the packet names, using exact paths and anchors. Distinguish target-project instructions from installed workflow references; reconcile mandatory project reading before dispatch rather than waiving it. No parent-chat/dirty-parent/inspiration dependency.
- **Verified dependency facts:** exact accepted revisions, actual merge evidence/references, relevant decisions and explicit branch ordering. Worker may rely on these unless inputs change or evidence conflicts; checkout and own acceptance proof remain independent.
- **Consult when needed:** historical dependency reports/checkpoints and other evidence, with exact references and the question that requires reopening them. Do not put routine history in read-now context. Reviewer evidence requirements remain separate.
- **Git contract:** actual bound root; expected initial full HEAD equal to the committed epic tip supplied at launch; clean or owned dirty tree and index; expected origin URL; named item branch to stay on (a generated branch only when this packet explicitly assigns that legacy route); expected upstream state (explicitly say when no upstream on a new branch is normal); first push destination; pull-request base (the epic branch) and any existing PR URL. Matching facts require one verification batch, not routine fetch/history/upstream repair. A detached or mismatched binding stops writes.
- **Ownership/authority:** allowed files/resources and exclusions; report/checkpoint paths; shared files the coordinator writes ([Record ownership](../../../../docs/agile-workflow.md#record-ownership)); other active owners; authorized external actions. Provider authority remains AGENTS plus explicit user overrides, not this reusable template.
- **Proof:** relevant pinned toolchain/controller/schema and local commands. The deterministic offline pre-PR gate is `npm run verify`. Name external skill validators separately when skill content changes and those validators cannot run in CI. Frozen hosted workflow/event/job/step/upload requirements on every current head, including artifact digest and provenance when this packet declares them. The packet may explicitly declare artifact verification not required (for example a docs-only change); the report then says so. An empty branch-protection set does not shrink that check set. Evidence/source-versus-PR-head mapping. State what cannot count green.
- **Continuation:** supported host mechanism. For a top-level T3 item thread, follow [T3 continuation](../references/t3-continuation.md#top-level-item-thread): link, watch, then the one catch-up snapshot in that section; if every declared check has already finished, verify and deliver in that turn, otherwise end the turn. One watch wake drives verification and one result to the named coordinator thread. The legacy parent relay is only for an explicitly selected delegated child. The worker retains diagnosis, repair, and current-head verification. Supply thread/item/worktree and actual task/run lineage when available. On resume, supply the last root, branch, full HEAD, and pull request, plus registration generation and last consumed event/snapshot where applicable. Do not assume the watch survived an interruption, that repair was unassisted, or that delivery is exactly once. Name the exact blocker owner and action if the route is unavailable.
- **Outputs/return:** exact owned report/checkpoint/evidence paths and an outline/example where structure is settled, using [report format](../../../../epics/report-format.md); return channel, next permitted action/stop boundary. For bounded spikes start small: question, procedure, observation table, result/limits; record observations during the trial and conclusions afterward. Pending/blocked returns are nonterminal ownership updates and still use that account when they are an item outcome or a user-attention blocker. Successful return requires independently verified current-head green checks, then coordinator acceptance/review and human merge remain separate.

For resume, add phase, ownership, last known root/branch/full HEAD/PR/check state; watch/registration generation, last consumed event, interrupted action, task/process/log handles and unresolved blocker. Worker opens the checkpoint first and reconciles relevant actual effects before repeating a mutation; no generic startup replay. Supply unknowable launch identities once in an actionable binding message when necessary, without an acknowledgment loop. Do not copy live status into reusable skill files.
