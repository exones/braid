# T3 delegation during coordinated delivery

Use only when the user requested delivery/delegation, not for a planning-only request. Obtain preferred model/provider/settings and WIP limits from the project's current `AGENTS.md` and decisions.

- Call `orchestrator_capabilities` before the first `delegate_task`, then follow current host rules on when to refresh it. Use the exact offered provider, model ID, and option keys. Put reasoning and other selected settings in `target.options`. Report unavailability without substituting a different configuration.
- Follow host routing for delegation; use T3 `delegate_task` for another provider, requested settings or a separate checkout. Do not create a top-level thread for a subagent. Generate the task from the worker's [canonical assignment packet](../../braid-worker/assets/assignment-packet.md) and explicitly load [braid-worker](../../braid-worker/SKILL.md), rather than copying an execution handbook. A child cannot assume parent chat history.
- Before isolated dispatch, commit every required context/dependency/checkpoint file at the full assigned revision and confirm its availability there. Supply exact accepted dependency revisions, actual merge evidence, explicit branch ordering, expected origin/initial HEAD/index, retained generated branch policy, push destination and PR base. Let the tool create/bind the checkout and return its actual root/branch; never create a child worktree in the shell or prompt. If the base is unavailable or changed, reconcile the mismatch before dispatch/transition.
- Use a shared checkout only for explicitly coordinated sequential work (including pre-Git analysis). Name existing dirty files/index owners, exclusions and allowed Git operations in the packet; do not demand destructive cleanup. Isolation does not carry uncommitted parent context. Preserve unexpected changes and stop only affected actions for reconciliation.
- Freeze the complete acceptance check set and supported continuation before dispatch. For T3 read the [parent-relay protocol](../../braid-worker/references/t3-continuation.md); parent registers/transports events and lineage, worker owns repair and independent current-head verification. Apply [shared delivery invariants](delivery.md); pending/failing/blocker returns are nonterminal, never successful handoff. Do not invent direct child watches or poll delegates/PRs.
- Keep coordinator/worker writes disjoint. Allow the single worker to finish before the coordinator inspects or changes implementation files in a shared checkout.
- Follow the tool's returned `next`. For an asynchronous result saying completion wakes the coordinator, end the turn; do not poll, sleep, or install a watcher. At a later completion turn reconcile the shared checkpoint and returned report against actual task/PR/head state. A waiting completion starts transport, not acceptance. At green handoff inspect via the returned root/branch/full HEAD (for example `git -C <returned-root>`); do not switch blindly to a branch occupied in another worktree. Reuse observed effects after interruption and preserve dirty/index ownership before any Git transition.
- Cancel replaced/unneeded delegate runs with `task_cancel`. New independent review/recheck assignments use a new `delegate_task`; read and apply the [review conventions](../../../../docs/agile-workflow.md#review-gates-and-indexing) when setting its title and output paths. Apply the host's current PR linking/watch rules if PR work is in scope.

If the host lacks delegation, provide the same filled canonical packet through the [manual handoff guide](../../../../docs/agent-handoff.md#manual-worker-assignment), naming the limitation and supported return mechanism. Missing transport is a precise blocker, not permission to lower delivery standards. Planning remains usable without T3; workers never invoke the coordinator skill to create a team.
