braid 0069 Precise notifications makes the board's phone pushes (ntfy) fire only when someone explicitly needs the user, and every push opens the thread that needs them. One rule in code, `forUser` (src/notify/message.ts), decides from the request record (`to`, `by`, `forwarded`, and its state through `routeOf`) whether a need pushes and which thread it opens. No new state file, state kind or mode setting.

What changed, by strand:

- 0069/A (PR #255): the leftovers. 0068's forwarded merge handover was lost because the board's PR lookup missed the story's PR, so `derive` read the Done-stamped story as Done and dropped its open review request; it is kept now (a found merged PR still wins). A failed one-shot limit push is retried at a later refresh, also on a two-project board. The weekly-limit details box says what to do (wait for the reset, or move the role in BRAID.md and resume); the still-over push says "stays paused" for one braid.
- 0069/B (PR #256): the one rule. Pushes: a request to the user (opens the asking thread, else the coordinator), an escalation by timeout or a gone PM thread (the asking thread), a forward, the PM's own request and a programme's stall (the PM's thread). Nothing else pushes: requests the PM handles, alarms (checks failed, a braid's stall), T3 pending questions, a Done-stamped story or strand PR with no request, a Done braid a programme runs. Every push has a click link, built from the thread id when T3 doesn't list it, else the body ends "Open the board". Under a PM a forward is the PM asking: it shows in the programmes panel as "The PM asks you: …" and the braid's card keeps its lane with "Waiting on the user, through the PM: …".
