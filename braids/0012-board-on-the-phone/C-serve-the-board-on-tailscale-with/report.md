`braid board --host <address>` now also serves the board on this machine's Tailscale address, for the Tailscale user who owns the machine only (D60).

What changed:

- `src/board/tailnet.ts` (new): `readTailnet` reads `tailscale status --json` (running, Tailscale IPs, MagicDNS name, owner login from `User[Self.UserID]`). It refuses when Tailscale is unavailable, not Running, has no address, or this machine is a tagged node, which has no owner. `tailnetAddress` accepts `tailscale` (the IPv4 address), one of the machine's Tailscale IPs, or its MagicDNS name. Everything else is refused with the reason, including `0.0.0.0`, `::`, LAN, public, `127.0.0.1` and other names. `whoisGate` runs `tailscale whois --json <ip>:<port>` and allows only the owner's login on a node without tags. Errors, unreadable JSON, a thrown runner, a non-IP peer, or a whois over 3 s all get false. An answer is kept 5 s per remote address, and concurrent asks share one call.
- `src/commands/board.ts`: one request handler serves two listeners. The `127.0.0.1` listener is unchanged (D50: token, Host, Origin). The Tailscale listener first runs the whois gate, then checks `Host` (address or MagicDNS name with its port) on every request. Actions also need a matching `Origin` when sent, plus `x-braid-request: 1` instead of the token. `open` returns 403 there. It listens on the local port number when that is free on the Tailscale address, else on a free port. `runBoard` parses `--host <address>` and resolves it before anything listens, then prints `On Tailscale: http://<MagicDNS name>:<port>/` and the login that may use it. Closing the local server closes the Tailscale one.
- Page: `postAction` always sends `x-braid-request: 1`. On a page not served from `127.0.0.1`, Open thread is only the `t3code://` app link, at every width, with no `open` button.
- Docs: docs/board.md "On Tailscale" (plus notes in "Actions and the session token" and "On the phone"), the `braid board` row and an example in docs/cli.md, and D60 with its log line in docs/decisions.md.

Does T3's phone app open the `t3code://` link? Per the source, yes. I read the official repository `pingdotgg/t3code` at 8cf97b5 (2026-11-18). `apps/mobile/app.config.ts` gives the production mobile app the scheme `t3code` (dev and preview builds use `t3code-dev` and `t3code-preview`). `apps/mobile/src/Stack.tsx` routes `threads/:environmentId?/:threadId?` to the thread screen. `apps/mobile/src/lib/appLinking.ts` handles `t3code:` links except the bare scheme and the Expo dev-client URLs. So `t3code://threads/<env>/<thread>` opens the thread, as long as the phone's T3 app is installed and connected to this PC's T3 environment, since the environment id comes from the PC's T3. I didn't try it on a real phone.

Validation: `npm run verify` passes (268 tests). `test/board-tailnet.test.ts` adds 14 tests:
- `--host` refusals: `0.0.0.0`, `::`, a LAN address, a public address, a non-Tailscale name, `127.0.0.1`, Tailscale down or logged out, no address, a tagged machine. Through `runBoard` these start nothing.
- The whois gate: owner, another user, a tagged node, an error, unreadable output, a hang (timeout), a thrown runner, and the cache.
- On the Tailscale listener: 403 for the page, the board data, the events and an action for every refused whois. The owner gets the page, the data, Start and Merge, and `open` gets 403. A wrong `Host`, wrong `Origin`, missing or wrong `x-braid-request`, or the local token in place of the header is refused, and `OPTIONS` gets 405. With `--host`, the local board keeps its token checks and `open`.

The listener binds 127.0.0.1 in the tests, because CI has no tailscaled. The existing board tests pass unchanged. I didn't run against the real tailscaled or a real phone: the brief allows only fake runners.

Open: the Tailscale URL's port is the local listener's port, a new free port on every run, so a phone bookmark breaks on restart. The refresh stream (`/api/events`) is checked when it opens. If tailscaled stops later, an open stream keeps sending its data-free "refresh" pings, and the requests those pings trigger get 403.

Decisions: the user chose the Tailscale identity, plain HTTP, the owner only, and the app link on the phone (2026-11-18). My own: the cross-site guard is a custom `x-braid-request` header, which can't be sent cross-site without a CORS preflight, rather than a second token the phone would need to get. The Tailscale listener reuses the local port number when it can. Exact MagicDNS FQDN or IP only: no short host name, no `localhost`. Failed whois answers are cached for 5 s too.
For later items: a fixed port option (`--port`) would let the phone keep a bookmark across restarts (`src/commands/board.ts` `runBoard`/`listen`). Try the app link and the board on a real phone over Tailscale. None captured as leftovers yet.
