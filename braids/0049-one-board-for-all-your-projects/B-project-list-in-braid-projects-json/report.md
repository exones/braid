braid now keeps a per-machine list of projects in `~/.braid/projects.json` (`{ "version": 1, "projects": [{ name, path, port? }] }`), kept with `braid projects add [<path>] [--name] [--port]`, `remove <name>` and `list`. Strand C will read it to serve several projects from one board.

- `src/projects/list.ts`: the strict reader (missing file → empty list; not JSON, another version, a bad entry, or a name or path listed twice (paths compared by `samePath`) → `ProjectsFileError`) and `updateProjects`, a locked read-modify-write that writes a temporary file and renames it. A file that can't be read throws before anything is written, so it is never overwritten.
- `src/commands/projects.ts`: `add` resolves the main checkout (`git rev-parse --show-toplevel`, then `mainCheckout`, so a worktree adds its main checkout), refuses a folder outside Git, a duplicate path (case-insensitive on Windows) or name, a bad name or port, and warns on stderr when another listed project has the same folder name (`~/braid-worktrees/<folder>/` would be shared). `add` and `list` print readiness from `readiness(path, null)`; a path that is gone is shown as a problem and the other projects still list.
- `src/braids/requests.ts`: `locked()` takes an optional `makeDir`, so the list's lock uses a plain `mkdir` and `~/.braid` gets no `.gitignore`; the repository stores behave as before.
- `src/cli.ts`: the `projects` command and its help lines; exit 1 for usage errors and a held lock, 2 for an unreadable list.
- Docs: the format in `docs/braids-format.md` ("The project list") with the command under Commands, rows in `docs/cli.md`, and a note in `docs/board.md` (Not ready) that strand C will read the list.

Validation: `test/projects.test.ts` (9 tests, run as `node dist/cli.js` with HOME, USERPROFILE, APPDATA, LOCALAPPDATA and XDG_* in a temporary folder) covers add/remove/list, adding from a worktree, the refusals, the folder-name warning and the four failure modes: a missing file (empty list, created by `add`), corrupt / unknown-version / bad-entry files (every command exits 2 and the file stays byte-for-byte the same), six `add` runs at once (all six kept; this test failed 3 of 3 times with the lock bypassed), and a path that no longer exists. A unit test of `samePath` (trailing separator, `..`, and on Windows case and `/` for `\`) and the duplicate-path corrupt case both fail if `samePath` is plain `===`. `npm run verify` passes (407 tests).

Decisions: GitHub is not checked by `add` and `list` (`readiness(path, null)`), because one `gh` call per project would make `list` slow and network-bound; the output says "GitHub not checked here". The name defaults to the main checkout's folder name. An unreadable list exits 2, as other format errors do. `locked()` got an optional `makeDir` rather than a copy of the lock code.
For later items: 0049/C can read the list with `readProjects()` from `src/projects/list.ts` (it throws `ProjectsFileError` for an unreadable file) and use `Project.port` for the fixed port. `samePath` and `folderKey` there compare paths and worktree folder names. A unique worktrees folder per project is still open (only the warning exists).
