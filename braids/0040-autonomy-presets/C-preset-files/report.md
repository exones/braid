Autonomy presets now exist as files, and braid can read and check them. A preset is one Markdown file: front matter with `name`, `merge` (`none`, `strands`, `all`) and `continue` (`yes`, `no`), a `# ` heading, then one table with one row per stop case and the columns `Case`, `Decide yourself when` and `Ask me when`. braid ships `careful` (the default), `steady` and `free` in `src/braids/presets.ts`, so they are compiled into `dist/` and the package needs no new files. A project's `autonomy/<name>.md` adds a preset, or replaces a shipped one with the same name. Nothing merges or decides differently yet; that comes in 0040/D and 0040/E.

- Brief field `autonomy` (braids only; a preset name; written after `delivery` and only when set), with `--autonomy <name>|none` on `braid new` and `braid edit`. The preset has to exist here. `braid view` shows `Autonomy: <name>` when it is set.
- `braid autonomy <number>` prints `Preset:`, `Name from:` (the brief, `BRAID.md` or the built-in default), `Text from:` (shipped, or `autonomy/<name>.md`, marked when it replaces a shipped one) and the preset text. When the brief has a `## Autonomy` section, it follows under `This braid:`. `braid autonomy --list` lists the presets available here and marks the default.
- `braid check` reports these as errors: an unknown key or value in a preset, a name that doesn't match its file, a missing heading or table, wrong columns, an unknown, missing or repeated case, and `BRAID.md` or a brief naming a preset that doesn't exist. It warns, in one line per preset and without failing, about a preset that delegates `security`, `data` or `outward`. It always checks project files for this, and checks a shipped preset only when `BRAID.md` or a brief names it, so an unused `free` stays quiet.
- `braid facts` counts `autonomy/` as `process`. The fact's text now ends "skill or autonomy preset changed".
- Docs: `docs/autonomy.md` (new; the format, where presets come from, the command, the checks and the three presets), `docs/braids-format.md` (the field, the older-CLI note, the `## Autonomy` section, check and edit), `docs/cli.md`, a README docs-table row, and decision D68. D66 and D67 are already taken.

Validation: `test/autonomy.test.ts` covers the shipped presets in `dist/` (they parse, and only `free` delegates the guarded cases), resolution from the built-in default, `BRAID.md` and the brief, a project file replacing a shipped preset, `--list`, set and clear with byte-for-byte equality, the strand refusals, every `braid check` error with its line, and the warnings. `test/facts.test.ts` adds an `autonomy/` change as a `process` fact. The gate (`npm run verify`) passes. On the first run, one existing test (`board-cheaper-reads`, "a hung git cat-file --batch …") failed under load; it passed alone and on the gate rerun.

Decisions: from the plan: the format, the three presets, the field, the command and the check rules (D68). My own:
- The preset text lives in a TS module rather than in `.md` files in the package, so `package.json`'s `files` stays as it is.
- `name` must match the file name.
- A preset needs a `# ` heading and exactly one table.
- The delegation warning covers shipped presets only when they are named.
- `braid autonomy` reads the brief from the same copy `braid view` uses (a newer one on a branch wins), and reads the presets from the working tree.
- `careful`'s `scope` row is the coordinator's mandate as the braid skill words it today.
