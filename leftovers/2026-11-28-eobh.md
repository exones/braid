Two tests fail on timing when the machine is loaded

On a full npm run verify while other braids ran their gates (0084/E, 2026-11-28), two tests failed and passed alone: the inbox test that expects an entry's age 0m got 1m (the clock crosses a minute during the run), and the lock-queue test reported "q is locked" after its 2 s wait. Both read wall-clock time against fixed limits, so a loaded machine makes the gate red without a code change; a fixed clock for the age and a longer or event-based wait for the lock queue would make them hold.
