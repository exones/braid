A retried braid start can skip the started event

braid start writes the started event to braid-requests after it creates the branch and worktree (0075/B). If that record write fails and the user retries, braid start says "(already started)" and may not write the event again, so the item reads only by its stored status (To Do) until its PR opens. braid start should write started whenever the record lacks it, even when the branch already exists. Where: src/commands/start.ts and the lifecycle writer.
