A stored To Do does not override a started event

braid edit --status is meant as a manual override that wins over the lifecycle record (0075/B, statusOf), and a stored In Progress or Done does win; but setting To Do on an item with a started event on braid-requests still reads In Progress, so a mistaken braid start cannot be undone by hand. Fixing it needs either a new event kind (for example reset) or a rule that a stored To Do newer than the started event wins. Where: statusOf and the lifecycle record (lifecycle/<item>.json).
