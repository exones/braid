A cancelled run next to a later success may read as failed

Since 0038, src/board/github.ts treats any CANCELLED item in statusCheckRollup as failing. This repo runs each ci check twice per head (two workflow runs, e.g. 44597271348 and 44597274712 on PR #163). If one run is cancelled (concurrency, a manual stop) and the other or a re-run succeeds on the same head, accept, handover and the board may read the PR as failed with no way to turn it green but a new commit. Untested against a live payload (review 0038). Fix: per check name, judge the latest run (by completedAt or run id) and ignore superseded cancelled ones, with a test.
