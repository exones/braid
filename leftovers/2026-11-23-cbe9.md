A merge leaving the grouped merge push re-alerts the phone

What: under a PM, when one merge leaves the group of merges waiting for the user (braid 0069/C), the board sends the group push again under the same sequence ID, so the phone may alert again for what is only a shrinking list. The update could be quiet (a lower ntfy priority, or no sound) when the set only shrinks.
Where: src/notify/message.ts (the merge group push), src/notify/notifier.ts (resend on a changed key).
Why: found in the PM live check of PR #263; an alert for nothing new is the noise braid 0069 set out to remove.
