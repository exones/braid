Run the board's git calls off the main thread

After 0077/B and 0077/G the board never calls git synchronously, but under a saturated machine /api/session still peaks at 0.4 to 2.4 s (0077/G report, PR #333): the remaining stall is child_process.spawn itself on the event loop (Windows). Moving the board's git spawns into a worker thread (about 60 to 100 lines, src/braids/gitio.ts async runner) would keep the request path under 1 s. Measure at the real 30 s refresh during 0077's final live check first; build only if the max still passes 1 s.
