A programme hold set only in the PM plan does not stop a board limit pause

What: a programme with state held but no braid pause --hold record is only a display hold (heldPauses); the board steerer locks on the pauses.json file, so it can still claim a limit pause on such a braid. The braid-pm skill writes both today; a PM that sets only the plan state would be bypassed.
Where: src/board/steerer.ts (targets), the programme hold reading (heldPauses), braid-pm skill.
Why: a deliberate hold must outlive a rate-limit pause (the rule from 2026-11-22-7kqa).
