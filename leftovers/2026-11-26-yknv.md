Push a record write onto the known tip without fetching first

After 0077/H (PR #346) one request-record write starts 10 git processes, but the lock is still held 3.6 to 7.5 s on a busy machine because each write fetches origin first and then pushes (src/braids/gitbranch.ts, writeBranchG). Pushing onto the tip already known and fetching only when the push is refused would cut a network round trip from most writes and shorten the lock that queues board writes.
