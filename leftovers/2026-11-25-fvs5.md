Repo cache key is case-sensitive on Windows

src/braids/repo.ts (0077/A) caches the main checkout and repo name by resolve(root). On Windows C:\code\x and c:\code\x are the same folder but two keys, so a caller that spells the root differently pays one more git call and keeps a second entry. Harmless, but the point of the cache is one read per root: normalise the key (lowercase on win32). Also test/git-cached-per-root.test.ts does not show that resetRepoCache drops an entry that was a hit.
