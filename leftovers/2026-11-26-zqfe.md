Board failure read: bound its thread show calls, and test the gaps the 0080/C review named

src/board/failure.ts (0080/C) reads a newly failed thread's error with one cached t3 thread show each, but fires them with an unbounded Promise.all: after a T3 restart many threads can fail at once and the board would start that many t3 processes in one refresh (on a loaded machine, the thing 0077 fought). Bound it like t3.ts's pool (6 at a time). The review also noted: no test that a failure reason does not show before the card reads stalled; docs/board.md's status wording vs needLine; the card's flex overflow on long reasons was not checked; the async-read guard test lives on 0077's branch, so this read is only covered by it once main (with 0077) merges in.
