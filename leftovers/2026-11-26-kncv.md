braid wait answers 3 on every short call when a cancelled run has no newer run yet

Found in 0078/C (PR #351), not new: when the CI run of a PR or braid branch head was cancelled under a newer commit that has no run yet, src/commands/wait.ts gives up on "no run" only after 5 minutes counted from the start of the call, so every short call (--timeout 0.25 or --once) answers 3 (still running) however long ago the cancel was. A coordinator reading CI that way never learns that nothing is running; judging the 5 minutes from the commit time (or the cancel) would fix it.
