The help-command test runs against the repository and imports dist/cli.js

test/cli.test.ts "every command named in the help is known to run" (0071/F, PR #288) calls run([name, "--nope"], root) with root being the braid repository itself, and imports dist/cli.js, which runs main on load. Today every command refuses --nope before writing (checked in review), but a future command that takes a free text argument could create braids, notes or request records in the real repo or push to braid-inbox. Run it in a temporary repo and import the run function without the main side effect. The same test skips by name the commands main handles before run (status, next, start, accept, facts, recap, handover, review, wait, board, notify, projects, clean); a CLI-level check for those would close the same gap that let braid eta ship unreachable.
