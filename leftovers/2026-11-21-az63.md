braid check does not validate docs.update in BRAID.md
D81 (0056) added a nested `docs` key to BRAID.md with `update: strand|braid|both|on-demand` and `public`/`internal` lists, but no CLI reads it: a typo such as `update: strands` is silently ignored and agents fall back to the default `braid`.
Where: the BRAID.md readers in src/braids/ (readiness, check) and test/readiness.test.ts.
Why: a project that sets the wrong value gets a different docs process than it chose, with no warning. A `braid check` (or readiness) warning for an unknown value would catch it.
