Tag main before each braid starts, for rollback

Before a braid starts (or before its final PR merges into main), braid creates a git tag on main, for example braid/0068/before, so the state before the braid can be found and restored at once if the braid turns out wrong.

Why: the programme pm/autonomous-dev-machine changes how braid itself works with every braid, and the user installs each one right after its merge; a known point to go back to makes trying each change safer.

Related: programme pm/autonomous-dev-machine ("After each merge"); scripts/Install-Skills.ps1 -Ref <ref> (could install from the tag to roll back the skills and CLI); AGENTS.md hard limit "Don't publish packages, create releases or tags ... unless the user asks".

- Tag at the braid's start or right before its merge into main (main moves in between)?
- Local only, or pushed to origin (AGENTS.md needs the user's yes for tags)?
