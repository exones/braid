Tag main before each braid starts, for rollback

Before a braid starts (or before its final PR merges into main), braid creates a git tag on main, for example braid/0068/before, so the state before the braid can be found and restored at once if the braid turns out wrong.

Why: the programme pm/autonomous-dev-machine changes how braid itself works with every braid, and the user installs each one right after its merge; a known point to go back to makes trying each change safer.

What the discussion found (2026-11-22, the PM and the user):
- main is not squashed: AGENTS.md says "Merge with merge commits", so a braid's final PR lands as one merge commit (for example 49095ceb, Merge pull request #245). Its first parent is main just before the braid; its second is the braid branch.
- git revert -m 1 <merge sha> already undoes the whole braid on main as one new commit: the braid's commits stay in history, their effect is removed. A tag would add only a readable name for parent 1.
- Two catches of any rollback, tag or not: merging the same branch again later brings nothing back (revert the revert instead), and braids merged after it that build on its code conflict or break.
- For this programme, "roll back" mostly means the installed skills and CLI, not the code: scripts/Install-Skills.ps1 -Ref <sha> installs any earlier state. A cheaper alternative: the PM's after-merge "have a look" message names the previous main sha and the one-line command to go back.

Related: programme pm/autonomous-dev-machine ("After each merge"); scripts/Install-Skills.ps1 -Ref; AGENTS.md hard limit "Don't publish packages, create releases or tags ... unless the user asks".
