Keep the ledger on its own branch

The ledger (the braids/ folder: briefs, logs, reports) would live on a separate branch that holds only the ledger, instead of in main next to the code, the way the inbox already lives on braid-inbox. Code branches and PRs would then carry only code, and ledger updates (planning, logs, "done" commits) would no longer touch main or the code branches.

Why: braid keeps getting slower. Since items started carrying references, tracking them, backlinks above all, has become expensive when the ledger is spread across main and the code branches. The braids-only commits also needed their own fast CI path (0026) and special handling in braid start (0019), which a separate branch would make unnecessary.

Related: 0020 Gap inbox (the braid-inbox branch is the precedent), 0026 Fast CI for braids-only commits, 0019 braid start on a planned story; README.md ("The ledger is the braids/ folder"), docs/braids-format.md

Open questions:
- One ledger branch for all braids, or one per braid next to its braid branch?
- How do workers, reviewers and the board read and write it: a worktree of the ledger branch, or braid commands as with braid note?
- What happens to the braids/ history already in main, and to epics/?
- How does a PR stay linked to its brief and report when they are on another branch?
- Which references and backlinks are the slow part, and how much faster would one branch make them?
