Checkpoints with a RESUME HERE section, for 0010

For 0010 (Runs, checkpoints, resuming): a long-running worker or coordinator keeps a progress file in its item: newest-first timestamped entries, and a "RESUME HERE" block at the top with the state and the exact commands to continue. The coordinator's snapshot uses fixed sections: Done since / Running / Needs a human / Open points. This answers 0010's open question by committing the summary while raw run records stay untracked.

Today: if a worker or coordinator session dies mid-item, the next session rebuilds state from git, the PR and maybe the chat. The braid's log gets an entry only per merged strand, so nothing is written during a strand (Windows worktree locks and interrupted waits have already hit this).

Example:
  ## RESUME HERE
  Branch braid/0010/B pushed at 4f2e...; PR #160 open, CI red on windows (path sep in logs.ts:88).
  Next: fix, npm run verify, push. Don't re-run braid start.

Utility: high when a run is interrupted, which is exactly what 0010 is for; this gives that item concrete content. Matters little for small 60-line items.
