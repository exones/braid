The board connects to T3 (its MCP endpoint, <environment-address>/mcp, OAuth sign-in by the user at the "Supervised" level; user decision 2026-11-25) and uses it to steer threads instead of only queueing messages: on Hold it interrupts every running thread of the held programme (coordinators, workers and delegated reviewers, found through T3's thread list, not only the board's own records) and then sends the hold words; on Resume it sends the go and retries until T3 answers (T3 off = retry, not give up). Later it can listen to T3's MCP Events to learn when a thread finishes instead of polling, which also helps board speed (P24). The sign-in token is stored through the host's secret store, never in files or logs. Goes with b1yb (Hold all) in P5 of autonomous-dev-machine.
