Re-read skills and the plan after a compaction

When a Claude session is compacted, the skill text it loaded is not loaded again: only CLAUDE.md, memory, the one-line skill listing and a model-written summary come back, so the PM and long-running coordinators drift further from their skill at each compaction. A project hook in .claude/settings.json, SessionStart with matcher "compact", prints one line after every compaction: "Context was compacted. Re-read your braid skill's SKILL.md and, for a PM, your plan file, then do Resuming." Optionally a PreCompact hook whose stdout tells the summariser to keep the active skill name and plan-file path, so the line can name the exact files. Codex threads need their own route.

Why: checked in the PM thread's transcript on 2026-11-23: after the compaction only a skill listing came back, and the plan file only as a reference ("too large to include"). The braid-pm skill already says to do "Resuming" after "a summarized conversation", but the model has to notice it was compacted.

Research (subagent, 2026-11-23; docs and T3 source, not yet tried live):
- Hooks (code.claude.com/docs/en/hooks): SessionStart matcher "compact" fires after auto and manual compaction and can return additionalContext or stdout as context; reloadSkills only re-scans skill directories, it doesn't re-insert a skill's text. PreCompact (manual|auto): its stdout becomes instructions for the summary (up to 10,000 characters); it can block. PostCompact gets the summary but can't add context.
- Agent SDK: settings-file hooks load through settingSources (on by default for query()); the SDK sends a compact_boundary message to the host.
- Who compacts in T3: T3 sends a plain /compact for a Claude thread over 200K tokens before the user's next message ("Keep full history" cancels it; apps/web ChatView.logic.ts, packages/shared claudeCompaction.ts, ClaudeAdapterV2 compactThread). The harness writes the summary (one model call, ~103 s here) and may also auto-compact itself. All five compactions in the local transcripts were trigger "manual" (T3's).
- T3 registers only SubagentStart and Stop hooks itself and sets no settingSources; with a custom Claude home it reads only project and local settings, so the project's .claude/settings.json is the safer place.
- Codex: T3 calls Codex's own thread/compact/start and re-injects T3's own additionalContext afterwards; Claude hooks don't apply.
- Agent self-detection (the summary's "This session is being continued…" phrase, counting compact_boundary lines) is unreliable: noticing is the step that gets forgotten.
