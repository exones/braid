braid list and view show what the board shows

Today `braid list` and `braid view` read only the checked-out `braids/` files, while `braid board`, `status` and `next` also overlay each item's brief from its braid and strand branches, local and `origin/…`, with the newest copy winning. So with a `main` behind GitHub, the board showed 0020 as Done and `braid list` still showed Outline. The idea: `list` and `view` read the board's sources by default, with `--files` for the checked-out files only. They also overlay `origin/main`, so an item merged with its branch since deleted still shows as merged; the board gains this too. And they warn when the checked-out branch is behind its remote ("main is 7 commits behind origin/main (as of the last fetch); git pull --ff-only"). No fetch by default, like the board.

Why: list, view, status, next and the board should always agree, without the user having to pull to read the plan.

Related: 0006 Read-only board (overlay from branches, docs/braids-format.md), 0005 Braids folder (braid list, braid view), docs/cli.md

Open questions:
- Whether a `--fetch` flag is wanted.
- Whether the behind-remote warning also belongs on the board.

In the user's words: "What would be your recommendation, like braid list --local and by default it would be remote or ?", then: "Capture as idea" (after the recommendation: board's sources by default, --files for the old view, overlay origin/main, warn when behind, no fetch)
