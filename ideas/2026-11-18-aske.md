Reviewer reads its rules from the base branch, not the PR

The braid-reviewer's worktree is detached at the PR's head commit, so it reads BRAID.md, AGENTS.md, the brief and the stop cases as the PR changed them. A PR that edits the skills, AGENTS.md, BRAID.md or its own brief changes the rules it is judged by, which happens often in this repo because the skills are developed here. The reviewer would read those rule files from the base branch and treat a diff to them as something to review, not as the new rules.

Why: the article's practice of always loading REVIEW.md from main so a change can't rewrite the rules that judge it.
