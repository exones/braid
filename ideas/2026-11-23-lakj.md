The update story: braid skills update and updating braid as a whole

`braid skills update` brings the installed skills up to the installed CLI's version, and more broadly braid gets one update path: the CLI, the skills for each provider and the running board service updated together and checked (versions match, the board restarted), from npm or a ref. Today this is scripts/Install-Skills.ps1 plus `braid board service restart`, run from a checkout of braid's own repo, which breaks when that checkout is behind (2026-11-23: the old script had no restart step).

Why: the user expects it to be "the whole update story which is bigger than just usability".

Related: scripts/Install-Skills.ps1, P7 · 0067 (service restart on install), braid skills install (sibling idea).

In the user's words: "also `board skills install` and `board skills update` I guess. Probably the second one will require the whole update story which is bigger than just usability"
